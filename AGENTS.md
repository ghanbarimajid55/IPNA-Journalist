# AGENTS.md

IPNA PMS — Persian (Farsi, RTL) performance-tracking app for a sports news agency. Plain PHP 8.0+ / MySQL, custom mini-MVC, **no framework, no Composer, no npm, no tests, no CI, no linter**.

## Toolchain / verification

- There is no build, test, lint, or typecheck command. Verify changes by running the app on a local Apache+PHP stack (e.g. XAMPP/WAMP) and exercising pages in a browser.
- PHP CLI is not on PATH on this dev machine; XAMPP's is usable as `C:\xampp\php\php.exe` (run `php -l <file>` on edited PHP files). XAMPP MySQL is `C:\xampp\mysql\bin\mysql.exe` (root/no password by default; start via `mysqld.exe`).
- A quick end-to-end smoke test: start MySQL + `php -S 127.0.0.1:8085 -t <projectRoot> <router>` (router emulates Apache FallbackResource and aliases `public/` assets), then exercise the installer → login → admin/reporter/photographer/API routes.
- **Install-detection heuristic gotcha:** `includes/init.php` treats `host=localhost AND dbname=ipna_pms AND empty password` as *not* installed. For local validation use a different dbname (e.g. `ipna_pms_local`) or a non-empty password, or you'll loop back to the installer.

## Bootstrap & install state

- `config/config.php` and `config/database.php` are **generated by the web installer** (`install/`) and are gitignored. On a fresh clone both are missing → every request redirects to `/install/`. `includes/init.php` tolerates a missing `config.php` (this was fixed in Phase 0; it no longer fatals before the redirect).
- `includes/init.php` requires `BASE_PATH` to be defined **by the caller** before it is included (`public/index.php` and `install/process.php` do this). Any new entrypoint must too.
- The installer writes a `.installed` marker at the repo root, rewrites `install/.htaccess` to `Deny from all`, and writes `install/web.config`. **Running the installer mutates these tracked files** — revert `install/.htaccess` and `install/web.config` before committing. To re-install: delete `config/database.php` (+ `config/config.php`), drop the database, and restore the original `install/.htaccess`.
- `BASE_URL` is hardcoded into the generated `config/config.php`; the front controller strips that prefix from request URIs so the app can live in a subdirectory. Always build links with `url()` / `Helper::url()`, never hardcode paths.
- Writable dirs required: `config/` (during install), `storage/` and `storage/logs/`.

## Class loading / routing

- **Autoloader:** `includes/init.php` registers `spl_autoload_register` that maps flat class names to files, e.g. `Admin_UserController` → `controllers/Admin/UserController.php`, `User` → `models/User.php`. There are **no PHP namespaces** anywhere.
- **Controllers are declared with an underscore, not a backslash** (`class Admin_UserController`, `class Reporter_ActivityController`, etc.). Route keys in `public/index.php` use the **same underscore form** (this was fixed in Phase 0; prior backslash keys 500'd). Keep route key and declared class name identical.
- **Reporter/Photographer are deduplicated (Phase 3):** role-parameterized base classes live in `controllers/Role/` (`Role_ActivityControllerBase`, `Role_TargetControllerBase`, `Role_ReportControllerBase`). `Reporter_*`/`Photographer_*` are thin subclasses returning `roleName()`, `viewPrefix()` (e.g. `reporter.activities`), `basePath()`. **The base appends a bare file suffix** (`.index`, `.create`, `.weekly`) to `viewPrefix()` — do not re-add the folder segment or you'll get `reporter.activities.activities.index`.
- Real routing is hardcoded arrays in `public/index.php` (`$staticGetRoutes`, `$staticPostRoutes`, `$parameterisedRoutes`). **Add new routes there.** `Router.php` was deleted (Phase 3) — it was never used for dispatch.
- Root `index.php` is only a FallbackResource-style shim that requires `public/index.php`; no root `.htaccess` is committed (point the docroot at `public/` or add one).
- Auth/role checks happen **inside each action** (`if (!Middleware::admin()) return;`, `Middleware::reporter()`, `Middleware::photographer()`), not in the router. Follow that pattern for new actions.
- Note: `BaseController` declares `protected function isAjax()`; child controllers must **not** redeclare it as `private` (PHP 8 fatals on visibility reduction). Don't add a private `isAjax()` to a new controller.
- **Global error handling (Phase 3):** `init.php` registers `set_exception_handler`/`set_error_handler` that log to `storage/logs/app-YYYY-MM-DD.log` and return a clean 500 (details only when `APP_DEBUG` is defined and true). New code should throw rather than silently fail.

## Database

- Single schema file: `database/schema.sql`, executed by the installer via naive `explode(';')` — no stored procedures, no custom delimiters in that file.
- **No migration system.** Editing `schema.sql` does nothing for existing installs; apply ALTERs manually to live databases.
- The installer's table-prefix option is ignored by the app (`includes/Database.php` and all models use hardcoded unprefixed table names). Leave the prefix empty.
- DB access is the `Database::getInstance()` PDO singleton, with **`PDO::ATTR_EMULATE_PREPARES => false`** — so a named placeholder must appear **once** per query. Reusing a `:name` twice causes `SQLSTATE[HY093]`. Use distinct names (`:t1`,`:t2`, …) or positional `?`.
- Models call `Database::lastInsertId()` (added in Phase 0) — it exists and delegates to PDO.

## Conventions

- Views: `$this->view('admin.users.index', $data)` → `views/admin/users/index.php`, auto-wrapped in `views/layouts/main.php` as `$content`; use `viewPartial()` to skip the layout.
- Escaping: `Helper::sanitize()` encodes on **input** (wrong layer); escape at **output** with `e()` (global) or `Helper::e()`.
- Global view helpers defined in `includes/init.php`: `url()`, `e()`, `csrf_token()`, `old($key,$default)` (returns the default — holds no sticky state yet), `jdate_month($m)` (Persian month name 1–12). Use `csrf_token()` — **not** `Helper::generateCsrfToken()` (that method does not exist).
- **Admin activity forms** submit a **Jalali** date (`date` = `Y/m/d`, possibly Persian digits) plus field names `activity_type_id`, `is_mission`; the controller maps these (`activity_type_id`→`activity_type`, `date`→`activity_date`, `is_mission`→`mission`) and converts via `Helper::jalaliToGregorian()`.
- **Admin list filters:** the UI uses query-key `activity_type_id`, but models (`Activity`) read `activity_type` — the controller maps between them. Sorting is whitelisted in the controller (`$allowedSorts`, `a.<col> <ASC|DESC>`).
- **Admin list views** expect `$pagination['currentPage'|'totalPages'|'perPage']`, plus `$search`/`$role_filter` (users) — controllers provide them. Don't rename silently.
- **Monthly targets**: schema columns are `news_target, exclusive_news_target, interview_target, special_report_target, photo_target, gallery_target, video_target, score_target`. Controllers/forms use these exact names (never `target_score`/`target_articles`/`notes`/`created_by` — those columns don't exist).
- **Activity types**: schema is `name, code, score, category, status`; `category` is ENUM `('news','photo','video')`. Do not use `score_per_unit`/`unit_label`/`sort_order`/`description`, and never insert a category outside the three valid values.
- **Reports/export:** report queries produce `news_count/photo_count/video_count` (category totals) plus `news_normal/news_exclusive/interview_count/special_report_count/photo_news/gallery_count/exclusive_video_count` (per-code). CSVs must read these aliases (never `articles`/`photos`/`videos`/`social_media`/`target_score`). Export cell values starting with `=+-@` are neutralized (`ExportController::neutralizeFormula`).
- **CSV import:** the form posts `import_file` (multipart) to `/admin/import/process`. Expected header row: `Name,Date,Position,Mission,Link,Description,News,Exclusive News,Interview,Special Report,Photo,Gallery,Video`. `Date` accepts `Y-m-d` or Jalali `Y/m/d`. `Name` auto-creates missing users (username gen needs no intl).
- **CSRF is enforced since Phase 1:** every non-GET/HEAD request runs `verifyCsrf()` in `public/index.php` (token from `csrf_token` form field or `X-CSRF-TOKEN` header). Any new POST/PUT/DELETE form or AJAX must include a valid token — views use `csrf_token()`; JSON AJAX must set the `X-CSRF-TOKEN` header (app.js does this via the `meta[name=csrf-token]`). A POST without a valid token returns 403.
- `BaseController::validate($data, $rules)` supports `required`, `email`, `numeric`, and `min` rules; the `numeric` rule is now actually enforced (previously dead).
- Log mutations with `Helper::auditLog()`.
- Auth session is `$_SESSION['pms_user']`; roles are `admin`, `reporter`, `photographer`. Login rate limit: 5 attempts / 15 min per IP via the `login_attempts` table.
- Timezone is `Asia/Tehran`; dates are stored Gregorian in the DB and displayed Jalali via `Helper::jalaliDate()` / the `TODAY_JALALI` constant. **Helper's Jalali math was rewritten in Phase 0 (correct); don't revert to the old algorithm, which was wrong.**
- Source files are UTF-8 and contain Persian UI strings; PowerShell console may render them as mojibake — that is display-only, not file corruption.

## Gotchas

- **Security checks (Phase 1):** session cookies are hardened in `includes/init.php` (httponly, samesite=Lax, secure on HTTPS) before `config.php`'s `session_start()`; CSRF is enforced globally; `API` controllers scope non-admins to their own data; exports neutralize CSV formula injection. `debug.php` was removed (Phase 1). Remaining Phase 2/3 items are listed in `AUDIT.md`.
- `public/sw.js` uses **network-first for page HTML navigations** and **cache-first for static assets** (CSS/JS/fonts/images) with a versioned cache name. Bump `CACHE_NAME` when you change app assets. POST/API requests are never cached.
- `config/`, `database/`, `storage/`, `install/` are `.htaccess`-protected; direct web access is blocked by design. `install/.htaccess`/`web.config` start permissive and `install/process.php` locks them (`Require all denied`) after install.
- Several views call vars that must be supplied by controllers (e.g. `$pagination`, `$search`/`$role_filter`); these are now provided. Logs for runtime errors go to `storage/logs/`.
- Several views call helpers/vars that don't exist yet (e.g. `views/admin/users/index.php` expects `$pagination`; `views/admin/team/create.php` uses `old()`). These are Phase-2 correctness items, not fatals after Phase 0/1.
- See `AUDIT.md` for the full Phase 0→4 plan and the list of remaining (Phase 2–4) issues.
